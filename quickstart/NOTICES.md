# Runtime notice inventory

The Docker image preserves the licence files of the source checkouts it builds:

| Component | Location inside the image |
| --- | --- |
| SDK | `/opt/indexus/sdk/LICENSE` |
| Dashboard / gateway | `/opt/indexus/dashboard/LICENSE` |
| Core | `/opt/indexus/notices/core/LICENSE` |
| Experiences / compiled browser app | `/opt/indexus/notices/experiences/LICENSE` |
| Compiled browser modules and collected third-party notice texts | `/opt/indexus/notices/browser/inventory.json` |
| MapLibre embedded-package notice texts and source-map provenance | `/opt/indexus/notices/browser/maplibre-upstream.json` |
| Go distribution used to build the binaries | `/opt/indexus/notices/go/LICENSE` |

The image carries notices from the exact input checkouts. When distributing a
build, provide the corresponding source for the versions you ship, including
local modifications and build scripts. For a modified Core serving remote users,
offer those users its corresponding source under AGPL section 13. Published
images built from earlier MIT revisions keep the terms of those revisions.
Keep these files readable by the image's unprivileged runtime user.

## Inspect an image

From the core checkout, with a locally built image:

```sh
INDEXUS_IMAGE=indexus/quickstart:scene-timeline
docker run --rm -i --entrypoint node "$INDEXUS_IMAGE" --input-type=module \
  < scripts/local/inspect-runtime-notices.mjs > runtime-notices.json
```

The script lists JavaScript package metadata in the shipped SDK, gateway and
global Node tools, declared licences and top-level notice files. It follows
package links once per physical directory and identifies test-fixture metadata
separately. It does not contact registries or change the container.

## Initial inspection, 17 November 2026

The inspected arm64 image contained 253 package metadata entries: 249 package
entries and four test fixtures. No scanned entry lacked a licence declaration.
Fourteen entries had no top-level notice file after the first-party notices
were added. That list includes fixtures and packages whose notices may be
covered by their parent distribution. It is a review list, not a conclusion
that fourteen packages are unlicensed or that every other package is cleared.
The base image separately contained 107 Debian package entries.

All four copied Indexus licence files were compared byte-for-byte by SHA256
against their source checkouts. The Go licence was readable in the runtime
image. Node's base image already includes `/usr/local/share/doc/node`; Yarn
also has its own distribution notice. The inventory is scoped to its declared
roots and does not claim to cover every file in those distributions.

## Browser build inventory, 17 November 2026

The build now inspects Rollup module metadata for both the main app and its
worker. An in-memory rebuild must reproduce every emitted asset byte for byte
before its package inventory is recorded. The current build has eight package
owners (six third-party, two first-party), 246 module IDs and 27 emitted assets.
The 27 assets were also hash-matched against the running quickstart image.

The JSON preserves the collected package-root/dist notice files, including
SunCalc's `LICENSE`: this browser dependency was not installed in the runtime
package roots, so the earlier runtime scan could not cover it. SunCalc 2.1.2 has
no `license` field in its package metadata; the actual licence text is retained
for review rather than inferred from that omission. First-party licence copies
remain at the separate paths listed above.

The inventory is generated by `scripts/local/inspect-browser-notices.mjs` inside
the Docker `web-build` stage and copied to `notices/browser/inventory.json`.
It is readable by the runtime user and is not a claim of legal clearance.
Upstream prebundled/vendored code, aggregate notices, copied public assets and
external resources still need separate review; module metadata cannot identify
every upstream component embedded in another package's distributed bundle.

## Runtime dependency pruning, 17 November 2026

The SDK production tree is now copied from a separate `sdk-runtime` stage after
`npm prune --omit=dev --ignore-scripts`. The build stage remains intact for the
browser inventory. In the same runtime scan scope, metadata entries decreased
from 253 (249 packages and four fixtures) to 231 package entries, with no
fixtures. The generated browser notice inventory and all 27 asset hashes remain
unchanged. Pruning build tools does not remove the need to review notices.

## Still required before public distribution

- Reconcile the chosen project licence, rights-holder wording, source files and
  package metadata through the approved publication process.
- Resolve the review list, checking parent/aggregate notices before adding or
  removing anything. Preserve the third-party terms that actually apply.
- Review the browser inventory and upstream prebundled/aggregate notices; the
  installed runtime scan alone does not identify every minified component.
- Review Node/Go binary notices and the base image's OS notices, and preserve
  applicable licence texts and source-offer obligations where required.
- Complete the sample data's provenance and attribution; see
  [DATA-PROVENANCE.md](DATA-PROVENANCE.md) for evidence and remaining gaps.
  Weather inputs include Open-Meteo distribution as well as Météo-France.
  Software notices do not cover these data or the IGN source products.
- Capture immutable image/source references and retain the release inventory.

This inspection is not a complete SBOM or legal clearance. No public image,
licence migration or data release is authorised by this inventory alone.

## Upstream MapLibre source-map review

The separate maintainer tool `scripts/local/inspect-maplibre-vendor-notices.mjs`
reads MapLibre's shipped main and worker source maps. It inventories candidate
embedded packages, preserves their mapped source hashes and compares those
files with installed dependencies. It also collects candidate notice texts,
including an explicit README licence section when no separate notice is found.

Run it against the matching experiences dependency tree:

```sh
INDEXUS_WEB_ROOT=/path/to/experiences \
INDEXUS_NOTICE_OUTPUT=maplibre-vendor-review.json \
node scripts/local/inspect-maplibre-vendor-notices.mjs
```

On 17 November, MapLibre 6.18.0's two maps identified 17 candidate packages.
All mapped files matched installed original files directly for 14 candidates.
The other three (`@mapbox/unitbezier`, `quickselect`, `tinyqueue`) first appeared
to lack mapped `.mjs` files in their installed package directories. Those files
actually ship under `@maplibre/maplibre-gl-style-spec/dist/node_modules`. Their
bytes match the parent source-map contents, and their own source maps point to
original `.js` files whose bytes match the installed candidates. Both main and
worker paths were checked: six complete chains, all 17 candidate packages traced.

The v2 report retains both direct comparisons and these nested chains. A direct
`.mjs`/`.js` layout mismatch is not itself evidence of a version mismatch. File
provenance still does not certify an entire package version or prove that code
survives final app tree shaking. Do not infer upstream build versions solely
from the lockfile.

MapLibre's 5,984-byte `LICENSE.txt` already includes the Mapbox, glfx.js and
d3-color sections. Its hash matches the text retained in the running image's
browser inventory. Those sections were not missing from the image.
The candidate `murmurhash-js` package has its MIT text in `README.md`, not a
separate LICENSE file. The review tool preserves that section and its source
hash; the first-level browser inventory did not separately inventory this
embedded package.

The Docker web-build stage now generates this v2 report with
`INDEXUS_NOTICE_REQUIRE_TRACED=1` and preserves it in the runtime at
`notices/browser/maplibre-upstream.json`. This profile refuses a mapped source
without a matching provenance chain or a package without a collected notice.
Missing-notice and missing-source fixtures both exercised that refusal without
emitting a report. The 17 texts and six nested chains were readable under the
runtime user on arm64 and emulated amd64; both inventories were byte-identical.

This is conservative notice retention, not legal approval or a claim that every
candidate survives final app tree shaking. Matching mapped files does not
certify an entire package version. Other nested prebundles, copied assets, data,
remote services and OS/runtime components remain separate review work.
No source licence or public distribution approval changes in this step.


## Local basemap style

The experiences source includes a local snapshot adapted from OpenFreeMap Dark,
itself a fork of OpenMapTiles Dark Matter. The code/design notices and
modifications are preserved in `public/basemap-notices.txt`, copied into the
Docker web build and served at `/basemap-notices.txt`. The vector source's
attribution links to that file as well as OpenFreeMap, OpenMapTiles and
OpenStreetMap. The style code is BSD-3-Clause and the upstream design notice
identifies CC BY 4.0; the full upstream notices are retained separately from
the Indexus software licence.

This style snapshot is local; the default tiles, font glyphs and sprites use
the OpenFreeMap public service. Their availability is an external dependency,
not part of the bundled sample or a claim of an offline basemap. No commercial
MapTiler style export, API key, subscription or licence migration is included.
